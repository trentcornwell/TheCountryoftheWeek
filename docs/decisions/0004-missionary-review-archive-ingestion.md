# ADR 0004: Missionary Review Archive Ingestion

- Status: Accepted for implementation
- Date: 2026-08-20

## Context

The site owner wants a new public tab giving access to *The Missionary Review of the World* (1888-1939), searchable by date, country, and person. The only source material on hand was `SVM/missionary-review-pdfs.txt`, a list of 721 links to scanned issues hosted at a third-party archive, cafis.org — no local text and no country/person metadata existed anywhere. This is new ground for the project: every prior content type (`country`, Prayer & Mission, Quick Facts) is either hand-authored or imported from a small, named, structured source. This is a large one-time bulk ingestion of someone else's already-published historical scans, with automated (not editorial) tagging.

`PROJECT.md`'s future roadmap already flags a related, *not yet built* feature — associating living missionaries' names with the countries they currently serve — as needing special care, since a missionary's name and location could put them at risk in a closed country. This archive is materially different: the people and events described are 85+ years old, and the source scans are already public at cafis.org. That said, the same instinct — don't overstate what automated tagging actually knows — applies here too.

## Decision

**Scope.** Fetch the 624 monthly issues and 52 yearly indexes (676 files); skip both duplicate file types in the source list — the 52 `*-combined.pdf` annual volumes (a concatenation of that year's 12 monthlies) and the one bulk `MRW-Indexes 1888-1939.pdf` (a concatenation of the 52 individual indexes).

**No local OCR.** Checked by hand before building anything: cafis.org's PDFs already carry an OCR text layer (`pdftotext -layout` extracts real, if period-typeset and occasionally noisy, text directly). No OCR engine is installed or invoked.

**Hosting: link out, never rehost.** The original PDF is never uploaded to this site's media library or DreamHost storage. Every issue stores only a `source_pdf_url` meta field pointing back to cafis.org, and the archive/single templates render a "Read the original scan" link. This sidesteps the open storage-quota and non-image-attachment questions `docs/DEPLOYMENT.md` leaves unanswered, and avoids taking on a licensing/rights position on cafis.org's own scans that this project has no basis to assert.

**Content model.** A new `mrw_issue` CPT (`theme/country-week/includes/cpt/class-mrw-issue-post-type.php`), mirroring `country`'s public/`show_in_rest`/rewrite shape but with a small flat meta registry (`Mrw_Meta_Fields`: `mrw_issue_key`, `source_pdf_url`, `volume_label`, `issue_kind`) instead of `country`'s large grouped quick-facts model — this content type doesn't need one. Two flat taxonomies, `mrw_country` and `mrw_person` (`class-mrw-taxonomies.php`). `mrw_country` term *slugs* deliberately reuse the same manifest `key` values as the `country` CPT (`scripts/import-missionary-review.php`'s `resolve_country_term_id()` enforces this), so a term can be cross-linked to the matching country page rather than living as a disconnected parallel list.

**Tagging is automated and explicitly unverified.** `scripts/mrw-fetch-extract.php` detects countries by whole-word matching against the canonical `country-manifest.json` names, plus a small table of unambiguous historical-name aliases actually used in this era's prose (Persia → iran, Siam → thailand, Ceylon → sri-lanka, etc.) — an alias is only applied if its target key genuinely exists in the current manifest, and ambiguous historical regions that later split into multiple modern countries (e.g. French Equatorial Africa) are deliberately left untagged rather than guessed. Persons are detected with an honorific + capitalized-name heuristic (Rev./Miss/Mrs./Dr./Bishop/Mr.), case-insensitive on the honorific to handle this era's frequent small-caps/all-caps typesetting. This is best-effort string matching, not NLP or verified identification, and both the archive and single-issue templates carry an explicit on-page disclaimer to that effect — consistent with `AGENTS.md`'s "never fabricate... religious/mission claims" and this site's existing practice of only crediting a source it can actually stand behind.

Piloting this against the full 1888 year (13 files) before writing this ADR's final form showed the country counts are not noise to suppress — a monthly "review of the world" issue genuinely surveys dozens of countries — so the per-issue country cap is a generous safety valve (120), not a meaningful limit; the person cap (80) is tighter since name-extraction noise is real (OCR line-break fragments and stray punctuation), and known artifacts (mid-word hyphenation, trailing possessives) are filtered at extraction time.

**Performance: server-side filtering, not client-side.** `archive-country.php`'s "render everything, filter in the DOM" approach (`country-filter.js`) fits ~196 countries but not ~670 issues plus free-text search — either the client-side item count or the JS/data payload would blow `docs/PERFORMANCE.md`'s 30 KB JS budget. Instead `Services\Mrw_Repository` builds a real, paginated `WP_Query` (`tax_query` for country/person, `date_query` for year range, native WordPress search for keywords) from a plain `<form method="get">` — zero new JavaScript, consistent with "JS only as progressive enhancement." The person filter is a text input with an HTML `<datalist>` (native browser autocomplete, matched by exact term *name*) rather than a `<select>`, since the person-term list can run into the thousands across 52 years — too large for a usable dropdown but fine as datalist suggestions.

**Import identity and idempotency.** `mrw_issue_key` (e.g. `mrw-1888-01`) is the stable identifier both scripts key off, the same rationale as `manifest_key` on `country` posts (ADR 0001): re-running either script after new/changed source data updates the same post/export file rather than duplicating it. `scripts/import-missionary-review.php` defaults to a dry run and requires `--write` to commit, following `reconcile-m49.py`'s dry-run-by-default precedent rather than `import-countries.php`'s (which has no dry-run flag at all, a known gap against `scripts/README.md`'s stated policy).

**Rollout staging.** The full 52-year fetch was deliberately not run before this ADR and the pilot batch (1888, 13 files) were reviewed. Scaling to all 52 years is a separate, explicit step.

## Consequences

- The archive is genuinely searchable by date (native `post_date`), country, and person on day one, entirely server-rendered, with no new client-side JavaScript or performance budget risk.
- Country/person tags are a browsing aid, not a citable index — this is stated on every archive/single template and in this ADR, not just implied. A future editorial review pass (spot-checking or hand-correcting tags) is possible later but out of scope here, same as `docs/DATA_MODEL.md`'s deferred fact-provenance envelope.
- No PDF is ever stored on this site's infrastructure; the archive is entirely dependent on cafis.org continuing to host the scans at their current URLs. If those links ever break, `source_pdf_url` becomes a dead link with no local fallback — an acceptable tradeoff given the alternative (rehosting ~3 GB of someone else's scans) was rejected above, but worth knowing if this is revisited.
- `mrw_country` terms double as a bridge to the `country` CPT (matching slugs) without any code coupling the two post types together — a future "missionary mentions for this country" block on a country page is a straightforward `tax_query`-by-slug away, but is not built here.
- This ADR's automated/unverified framing is a narrower, explicitly time-scoped answer to `PROJECT.md`'s "missionary names per country" flag — it does not resolve that future, living-missionary feature, which still needs its own safety-first design when it's picked up.
